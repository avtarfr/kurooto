Voice (modules/voice/, 0.8.8)

Kurooto speaks on the computer it runs on (Kokoro-82M by default, Piper as the lighter choice) and, with voice.listen.on, listens to the room all day. Every decision about what it hears is made on the computer; only turns the gate calls *addressed* reach the AI you picked, through the portal. Off by default (Module off until enabled), with listening a second switch. User page: ../user/voice.md.

Outputs: playing the voice elsewhere (0.8.12)

Voice.add_output(fn) -> remove() lets an add-on play Kurooto's voice on another device instead of this computer's speakers. fn(pcm: bytes, sr: int, stop: threading.Event) -> bool:

  • Called by Speaker._play for each sentence's sound (16-bit little-endian mono PCM at sr), newest output first. It blocks until that sound has finished playing, or until stop is set, and returns True when it played it, False when it can't now; the next output is asked, finally the local Player. An exception counts as False, and is logged once per output as voice_failed {part: "output", error}.
  • Threading. It runs on the speaking thread (voice-say, or the caller's with wait=True) inside Speaker.lock, so outputs are never called concurrently and sentences stay in order. busy is true the whole time, so holding() keeps the microphone held while the other device plays, plus the usual 0.4 s tail, exactly as for the Player. Registration takes a separate small lock, never held while sound plays: add_output and remove() are safe from any thread, and a change takes effect from the next sentence. remove() is idempotent and removes only its own registration (the same fn may be added twice).
  • Stopping. stop is Speaker._cancel: Speaker.stop() (/voice stop, mute, Voice off) sets it, and the sentence loop ends; after a stop nothing falls back to the Player. It's cleared when the next utterance starts.
  • Unchanged: voice_speak is published as each sentence starts, wherever it plays; status() still names the local player. The sound is handed over in memory only; the output must not write or keep it either.

Auto gain (audio.Gain, 0.8.17)

voice.listen.auto_gain (on), voice.listen.auto_gain_snr_db (6). Listener(gain=Gain(snr_db)): while no stretch is open, each frame with VAD < 0.35 updates the noise floor (an EMA over NOISE_S 4 s of its RMS); a stretch starts only when VAD >= 0.5 *and* the frame's RMS >= max(FLOOR, noise) * 10^(snr_db/20) (loud_enough; nothing known yet: yes). When a stretch ends, Gain.level(pcm, flags) scales it so its speech frames' RMS reaches TARGET (0.08), never turning it down, at most MOST (8x) and never past 95% of full scale. VAD and barge-in see the raw frames; only the stretch handed on (transcriber, Voice ID, gate) is levelled. status()["auto_gain"] shows noise_db and the last gain. The system's microphone volume is never touched.

Barge-in (barge.py, 0.8.13)

voice.listen.barge_in (on). Before it, Listener dropped every frame while hold() (Speaker.holding() or portal.busy). Now Listener(barge=Voice.barge) asks Barge.wants() per frame first: true while Speaker.holding() (speaking, plus its 0.4 s tail), and while a stretch that barged in (or has a check in flight) goes on after it stopped. Then the frame and vad.prob(frame) go to Barge.feed() and the normal path never sees it (the VAD is reset on the way in and out, the wake word buffer and pre-roll cleared). Off, or the portal busy only thinking: the old drop. Nothing else in the listener changes.

  • What's played. Speaker._speak calls barge.speaking(pieces) (their words, memory only, for the echo words check; it queues making its own voice print when the voice check can run) and Speaker._play calls barge.played(pcm, sr) as each piece starts, wherever it plays: per-32 ms RMS levels with the start time. Both only while the listener runs. expected(now) = the loudest level over [now - ECHO_LAG_S (0.8 s), now + 0.05], which covers an add-on output's delay (a phone next to the laptop) and the room.
  • The echo's share. Each speech frame (VAD >= 0.5) heard while something audible plays adds level / expected; gain() is the median of the last GAIN_FRAMES (125, ~4 s), needing GAIN_MIN (15). Not added while a stretch is confirmed. A frame is *loud* when level > max(FLOOR 0.01, LOUD_X 2.5 * gain * expected).
  • Stretches are cut as the listener does (start 0.5, 700 ms below 0.35 ends, 320 ms pre-roll, 15 s max), each with an id. A check is queued when the stretch has MIN_SPEECH_S (0.6 s) of speech or LOUD_MIN_S (0.3 s) of loud speech, again every RECHECK_S (0.5 s) more, one in flight at a time; when the stretch ends unconfirmed (with a check in flight or 0.3 s+ of speech), a final check of the whole of it.
  • check(), on the voice-barge daemon thread (sync = True in tests runs it inline): (1) the voice, when Voice ID is on, has no problem() and its own print exists: VoiceID.embed(pcm), owner = dot(e, centroid), itself = dot(e, own); barge when owner >= thresholds(t).pick(speech_s).accept and owner - itself >= SELF_MARGIN (0.10). (2) Else loudness then words: loud frames >= 0.3 s and >= half the speech frames, then Voice._write_out(pcm); words_ok(): real words (not made_up()), a told-off phrase always, else fewer than ECHO_WORDS (60%) of them in what it's saying.
  • On a barge-in the checking thread calls Speaker.hold() (0.8.17; it was stop()): the piece playing is cut (the Player, and the per-piece event an add-on output was handed, Speaker._piece) and the sentence loop waits in Speaker.say_piece(). barge_turn() then settles it: told off or a new turn -> stop(); anything else ("mm", no face) -> release(), and say_piece() plays the cut piece again from its start and goes on (event outcome resumed). Never settled within HOLD_MAX_S (12 s): it stops. It publishes voice_state hearing, why "barged in". The stretch is still collected to its end, then Voice._heard_audio(..., barge={"sid", "how", "score"}) queues it like any stretch (never blocking the listener); _work_one sends it to Voice.barge_turn().
  • barge_turn(pcm, flags, how) on voice-hear (after the interrupted portal.take has returned): written out; _pending = None (the interrupted turn isn't learned from); told off (with voice.listen.told_off) -> _told_off() (misfire, close); else the verdict: how == "voice" -> Verdict(OWNER, "your voice, over its own"), loud with Voice ID on -> VoiceID.check(pcm, speech_s, adapt=False) (never adapted from: its echo may be in it); asks() -> portal.take(h, Decision(ADDRESSED, 0.9, "barged in"), text=uncall(text), who) (the chat's context carries, as any turn); anything else -> Portal.listen_on("barged in", who) (open, answered, last and spoke_at now, so the follow window and tick() hold it for follow_s). Event voice_barge {how, outcome} (voice/loud; told off/turn/listen), never words. status()["barge_in"] = {on, since_start}.
  • Its own voice print: own_print() synthesizes OWN_PHRASE with Voice.tts(), voiceid.resample() to 16 kHz, VoiceID.embed(); cached in memory per (Voice._tts_key, VoiceID.model()), never played or saved. No engine or no model: [], and the voice check doesn't run (fail closed: only loudness).

The flow

Mic (sounddevice | pw-record | parec), 16 kHz mono, 512-sample frames
  -> Listener (thread "voice-listen"): levels -> voice_level; held while Speaker.holding() or the portal is busy
       wake word (only with your own openWakeWord .onnx, 1280-sample steps) -> woke_at
       Silero VAD per frame: start >= 0.5, end after 700 ms < 0.35, max 15 s; 320 ms pre-roll (a deque in memory)
  -> Voice._heard_audio: queue (max 3, oldest dropped)
  -> worker thread "voice-hear": Voice.hear(Heard(speech, wake, seconds, ended_at), pcm)
       blocked()? drop.  Whisper.text(pcm) (CPU, int8; the assistant's name as initial_prompt and hotwords) -> del pcm
       Gate.decide(heard, portal.context())
       told off -> _told_off(); else face_check() (need_face: a face close and facing, or chatter)
       not addressed: heard.text = "" (dropped), its loudness outline -> voice_heard, portal.take() closes an open portal
       addressed: NameMatcher.uncall() (the call isn't sent); portal.take(heard, decision, text) -> ask_brain(text) -> Speaker.say(reply)

Voice.background() (the module's long-running coroutine, app.start_background) runs every second: works out blocked() (0.9.0: also "your phone is out" with voice.listen.phone_away, from core/nearby.py:phone_out, set by Brain's phone places sensor; see face.md), starts or stops the listener, closes the portal when blocked, and calls Portal.tick(). The listener and the worker are daemon threads; the coroutine never blocks the loop. heavy = True: in saver mode on battery power.may_run keeps it from starting, and blocked() says so.

blocked() reasons, in order: listening is off, muted (state/voice.json), Kurooto is paused, on battery (saver mode), you're on a call (web/tools_api.py:live_call, unless voice.listen.calls), night hours (core/availability.py:Availability.night, only with voice.listen.night off; it's on by default), not set up yet.

The gate

gate.py's docstring is the spec; in short, first match wins:

  1. no speech (VAD) -> noise, 1.0
  2. your own wake word model fired (voice.listen.wake_word, an .onnx path; empty by default) -> addressed, 1.0
  3. empty, or a transcriber's invention from silence (MADE_UP) while the portal is closed -> noise, 0.9
  4. its name as a call, the default wake (first, after an optional "hey/ok/hi", or last; one to three words joined; you.assistant_name and "Kurooto", through names.py:NameMatcher) -> addressed, 0.95
  5. the portal is awaiting (its name or the wake word alone opened it) -> addressed, 0.9 5b. (0.8.17) ctx.looked (a look opened the portal, nothing said since), voices < 2 and ctx.speaker != "guest": addressed, 0.9, why LOOKED ("looked at"); when careful (ctx.careful and ctx.unconfirmed()) or in conversation mode only if asks(text), else it falls through to the rules below. Never vetoed (not borderline).
  6. voices >= 2 -> chatter, 0.8 (the listener doesn't count voices yet: Heard.voices stays None)
  7. portal open, within close_s, and a question (?, QUESTION) or request (REQUEST) -> addressed, 0.85
  8. within after_speak_s of speaking, a question or request; REPLY words (yes/no/sure ...) only when what it said ended in "?" -> addressed, 0.8
  9. the local model (Voice.judge: providers.local() only when its base_url host is loopback, else the offline helper's _generate; None otherwise), with PROMPT and context lines (the open conversation, its last reply, how much unaddressed talk in the last minute, a mid-sentence mention of its name). parse() takes the first {...} JSON, else a single class word at 0.5, else chatter at 0. Addressed below voice.listen.threshold -> chatter. No model, no answer, or model_judge off -> chatter, 0.0.

The prompt (gate.py:PROMPT):

You decide whether speech heard near a computer is spoken TO its voice assistant, called {name}.
It was written out by a speech recogniser, so words may be wrong.

Heard: "{text}"
{context}
Answer with JSON only, like {"class": "chatter", "confidence": 0.8}. The classes:
- "noise": not real speech meant for anyone (a TV, music, a cough, words with no sense).
- "chatter": people talking to each other, on the phone, or to themselves; {name} mentioned in passing.
- "addressed": a request, a question or an answer meant for {name}.
When unsure, answer "chatter" with a low confidence.

Its name (names.py)

The default wake is the name heard by faster-whisper; openWakeWord's ready-made models (CC BY-NC-SA 4.0) are never fetched. Whisper gets the name as initial_prompt ("Kurooto.") and hotwords (dropped on a TypeError from a faster-whisper before 1.0.2). NameMatcher(names, variants):

  • spellings: each name joined without spaces, MISHEARD[name] for the default "kurooto" (kuroto, kurouto, kuruto, curoto, kurato, "kuro to", "coo roto", kirito, "guru to", kuroo, kuro ...) and voice.listen.name_variants; one to three adjacent words are joined before comparing, so spacing doesn't matter.
  • near misses, against the names themselves only (a mishearing as the target would let "kurt" match "kuroto"): 4+ letters, at least 2 vowel groups and within 1 of the name's, the same skeleton() (consonants with c/k/q/g, t/d, r/l, b/p, v/f, s/z merged; vowels, h, w, y dropped; doubles once), and Levenshtein distance() <= 2.
  • called(): at the start (after one of CALLS) or the end; anywhere() for the model's context line; uncall() removes the call before the turn is sent.
  • (0.8.13) kind(joined): EXACT (a name itself), KNOWN (a mishearing or variant), NEAR (fuzzy only). A span that is its own or a known spelling wins over a longer near miss ("Kurooto I need" was "kurootoi", a near miss, and swallowed the "I"). call(text): where (first / last / middle), kind, greeted and rest.

Pieces, not single sentences (0.8.13)

Speaker._speak used to synthesise each sentence alone. Kokoro picks its style vector by the number of phonemes (voices[name][len(tokens) - 1]) and a few words alone come out hurried and flat. With voice.speak.join_sentences (default on) shape.join() packs consecutive sentences into pieces of at most 200 characters (120 for the first, so the first sound is ready about as soon as before), after max_chars has cut the answer; a line with no closing mark gets a full stop so a list item still ends. Inside a piece the model makes its own pause at each full stop (about 0.1 s: Kokoro v1.0's ONNX export has no duration output, so kokoro-onnx can't top those up). Voice.shape() joins the same way. Outputs (add_output) get a piece per call instead of a sentence; the sample rate is unchanged. Sentences longer than 220 characters are still split at commas by sentences(); join() never cuts.

Between pieces, pause_after(tts, piece, sr) appends silence to every piece but the last (and in Voice.shape()'s engine path): kokoro-onnx's create() trims leading and trailing silence (trim=True, librosa's 60 dB trim) and adds sentence_pause 0.25 s or clause_pause 0.1 s only between batches of one call, so separate calls ran together. The same values are used: 0.25 s after . ! ?, else 0.1 s. Piper keeps its silence and gets none. The pause is part of the PCM, so outputs, voice_speak's shape and holding() all include it.

The sample rate is Kokoro's own (kokoro_onnx.config.SAMPLE_RATE, 24000) from Kokoro.create(), passed unchanged from Kokoro.synth through _play to each output and the Player (pw-play --rate, paplay, aplay, sounddevice, WAV headers); nothing resamples it on the way out. (Voice ID's synthetic impostors resample a copy to 16 kHz for the embedder only.)

Numbers as words (0.8.13)

Kokoro's pronunciation comes from espeak-ng, which reads digits literally ("21:31" → "twenty one : thirty one", "0.8.13" → "zero. eight point one three", "₹3,000" → "rupee three thousand", "12 GB" → "gee bee"). With voice.speak.numbers_as_words (default on) shape.spoken(text, numbers=True) runs numbers.say() after clean() and before the text is split into sentences, so "a.m." no longer ends a sentence. It's applied to the speech engine's input (Speaker._speak) and to both shape paths (Voice.shape: the engine's and the estimate's), never to voice_text or anything shown. Passes in order: dates, versions, ranges, times, money, percentages, decades, units, "/month", ordinals, years, fractions, ratios, "1920x1080", "±", minus signs, letters joined to digits, then any number left. Each pass only touches a number standing on its own (LEFT/RIGHT: not inside a word, a decimal or a code-like token), so 7c12897, x86_64 and 0x1F stay as written. AM and PM are written A-M, P-M: espeak reads a bare "AM" before a full stop as the word "am". Years: 1900 to 2099 always, 1100 to 1899 after a year word (in, since, by ...) or a month. Indian commas (1,00,000) are read in lakhs and crores. Check a reading with the Kokoro tokenizer's phonemize(text, "en-us") (phonemes only, no sound).

The model

CAM++ from 3D-Speaker (Apache-2.0), ONNX by sherpa-onnx (Apache-2.0): campplus-en (VoxCeleb, 512-d, default) or campplus-multi (zh+en, 192-d), parts model:voiceid-campplus-en|multi with pinned sha256, and pkg:voiceid (kaldi-native-fbank). CPU only (CPUExecutionProvider, 2 intra-op threads; the GPU is the local AI's). The front end comes from the model's metadata (sample_rate 16000 only, normalize_samples, feature_normalize_type: global-mean, output_dim); fbank: 80 bins, dither 0, snip_edges, 25/10 ms. About 50 ms per 3 s turn on a Ryzen 7 7435HS by the spec's bench (not re-measured in this build). The model loads on first use and is dropped on Voice.stop() and when the switch goes off.

The flow change in hear()

with voice.speaker_id.on and .gate (default):
  VAD speech -> who = voiceid.check(pcm, speech_s)          # before any transcription
    not owner, no wake word, portal closed:
      Whisper on the first and last 2 s only (_edges); its name not called -> chatter, dropped, never written out
  Whisper (all of it) -> Gate.decide(heard, ctx + conversation) -> portal.take(..., who=who)
with .gate off and voice.listen.conversation_mode on (default): who = voiceid.check(pcm) for every stretch of speech
  (so another voice still starts conversation mode), then Whisper (all of it) -> Gate -> portal.take(..., who)
with both off: Whisper -> Gate -> addressed only: who = voiceid.check(pcm) -> portal.take(..., who)

Heard.speech_s is the VAD's speech time (the listener now passes per-frame flags as a 4th argument to on_speech), not seconds (which includes the pre-roll and tail). The portal counts a session per opening, keeps last_owner_at/last_owner_session for carry, publishes voice_text {who: "you", speaker} (the decision word, never the score), calls send(said, who), and prefixes the guest notice once a session per kind. owner_only_at_all: nothing published or sent; "I only answer my owner's voice." at most once a minute (each call opens a new session). ask_brain builds Incoming(speaker=who.decision, speaker_by="voice").

Conversation mode (Context.conversation): set while biometric.others_present() (a guest voice in the last voice.listen.conversation_s, or a face part's signal) or three guest voices in two minutes. Then the gate takes its name only with a question or request after it (or nothing), the wake word, the turn right after them, and a follow-up within conversation_follow_s of its answer; rules 7 and 9 (open portal, local judge) don't apply.

decide() and calibrate()

decide(score, t, speech_s, ctx): missing / locked / model failed -> unsure; voices >= 2 -> unsure; short turns (< 2.5 s of speech) use t.short; under min_speech_s: owner only by carry (same portal session, within carry_s, score >= unsure; never in strict), else unsure; score >= accept -> owner; >= unsure -> unsure; else guest.

0.8.13, in the >= unsure band only and never in strict: face_assist and ctx.face_owner (VoiceID.face_owner(): nearby.view() says one face, the owner's, at most VIEW_S 5 s old; set from Face presence's watcher view emit each frame, cleared when the camera closes) -> owner, FACE_WHY, assisted; carry_talk and ctx.portal_open and the same session and within carry_talk_s (max(carry_s, listen.follow_s)) of last_owner_at -> owner, TALK_WHY, carried. Rules come from VoiceID.rules() (voice.speaker_id.face_assist, carry_talk).

calibrate(samples, bank, synthetic, strictness, margin, threshold): n >= 12; outliers by leave-one-out (g_i < median - 3 * 1.4826 * MAD and < 0.30, at most 10%, named by condition); centroid = normalised mean; held-out genuine scores (long, and the 1.5 s crops for short) against c_-i; impostor scores from the bank (full + 3 s for long, 1.5 s for short, plus Kokoro's 30 synthetic vectors when Kokoro is set up); per set accept = quantile(I, 1 - far) with far 1% / 0.2% / 0 (strict: max(I) + 0.03), clamped to [0.30, 0.85]; unsure = min(quantile(I, .99), accept - margin). Grade: good (FRR_long <= 5%, FRR_short <= 15%, median genuine - accept >= 0.12), fair (FRR_long <= 15%), weak (saved only with Use it anyway). threshold > 0 overrides accept for both, applied at check time from the stored calibration so it takes effect at once; strictness and margin need a Retrain. The override is held to OVERRIDE (0.30 to 0.95) and the margin to 0..MARGIN_MAX (0.2) wherever they're read (override(), band(), margin_of()): a typed 0.05 can't make a stranger "you", and a wide margin can't let any short reply carry.

The bank. tools/voiceid_bank.py over LibriSpeech dev/test (146 speakers x 4 utterances x {whole, 3 s, 1.5 s}, about 1,750 rows; optionally Common Voice's India and South Asia accents with --cv), float16, one file per model with the model's sha256 in its header. Train refuses when it's missing or for another model. Not in this commit: building it needs LibriSpeech (about 1.3 GB) and the two model files downloaded; see "Not verified".

Evaluation (tools/voiceid_eval.py)

Each LibriSpeech dev/test speaker is enrolled through enrol.Session (stt off) from his largest chapter, the conditions made from the clean reading (quiet -14 dB; far -10 dB and a synthetic room, RT60 0.45 s; noise: pink at 10 dB under the speech, VAD flags from the speech before the noise, as Silero would find it; short requests 1.2-2.5 s; free 11 s), then calibrate() at each strictness and Verifier.check() for 8 held-out utterances per speaker (another chapter where there is one), whole (up to 8 s) and cut to 2, 1.5 and 0.8 s, against every stranger in its group. What it says: the targets in FAR (1 %, 0.2 %) are per impostor *row*, but a few look-alike voices carry most of the misses, and a set of 146 speakers can't place a cut-off at 1 in 500 of the whole population (that needs more speakers, not more rows): relaxed and normal pass strangers about 1.4 and 2.8 times as often as their targets. With fewer speakers in the set it gets worse (18, 36, 73 speakers: 2.2, 1.1, 0.58 % at normal, halves). The defaults weren't changed: the miss rate is set by how many speakers the set has, the owner-side cost of a higher cut-off can't be measured on clean audiobook speech, and strict (0.13 %) is there for a room with strangers. A bigger impostor set (more speakers, e.g. Common Voice with --cv) is the real fix. Limits: read speech, mostly clean, one microphone a chapter; simulated conditions; strangers, not relatives.

Adapter

Takes a turn only when: owner by "your voice" (not carried), score >= accept_long + 0.08, speech >= 2 s, not two voices, under adapt_per_day; FIFO up to adapt_max; centroid = normalize(0.75 * enrolled + 0.25 * mean(adapted)); drift guard cos(new, enrolled) >= 0.95, else drift_stopped; thresholds derived again after each take. Undo today / all.

0.8.13: consider(..., face=True) takes a face-assisted owner verdict with score >= the stored long.unsure instead of accept + 0.08 (the other checks the same); the entry is marked face: true (counted in status()["adapt"]["face"]). VoiceID.check() keeps such a turn's vector in memory (_face_last); Voice holds it with the turn and calls learn_face() only when the turn went well (adapt and face_assist on); told off or closed, it's dropped.

Sound streams and threads (0.8.16)

The crash: 0.8.10 to 0.8.15 died with SIGSEGV in snd_pcm_poll_descriptors_revents / snd_pcm_status (libasound, under libportaudio's blocking read, called from a Python thread through cffi), and once with SIGABRT "corrupted double-linked list". Listener.stop() ran Mic.close() on the caller's thread (the asyncio loop, or enrolment), which did stream.stop(); stream.close() while the voice-listen thread sat in stream.read(): PortAudio freed the ALSA PCM under the read. Crash addresses like 0x100 and 0x10 are calls through the freed PCM's function table.

The rules now:

  • One owner per stream. The thread that iterates Mic.frames() opens, reads and closes the PortAudio stream (or the recorder child). Player.play() opens, writes and closes its own RawOutputStream, one per sentence, under Player._lock. Nothing else touches them.
  • Stopping is a flag. Mic.close() and Player.stop() set an event; from another thread they only terminate() a child process (by its own pid), which is safe because no native code is shared. Listener.stop() then joins the reader for up to JOIN_S (0.5 s) so the next Listener doesn't open the device while the old one holds it, and Listener._run closes the frames generator on its own thread in finally.
  • No blocking PortAudio calls on our threads for input. The microphone runs in callback mode: PortAudio's thread puts frames on a queue (QUEUE_FRAMES, oldest dropped), and the reader takes them with a 0.1 s timeout, so it sees a close at once. Output writes 50 ms pieces (PLAY_CHUNK_S) and checks the flag between them; sd.play()/sd.stop() (one module-wide stream) are no longer used.
  • Reopen, don't die. A stream that goes inactive or sends nothing for STALL_S (3 s), or a recorder that exits by itself, is closed by its owner and opened again after REOPEN_S doubling to REOPEN_MAX_S; Mic.reopened counts it. The first open failing raises at once (Voice reports it and retries after RETRY_S), and REOPEN_TRIES (6) tries in a row without sound raise "the microphone stopped sending sound".

voice.audio.backend (auto | pipewire | portaudio): backend(choice, device) makes it concrete. auto is pipewire when pipewire_running() (Linux, pw-play and pw-record on PATH, the user's pipewire-0 socket under PIPEWIRE_RUNTIME_DIR/XDG_RUNTIME_DIR, or PIPEWIRE_REMOTE) and voice.listen.device is empty, since that setting holds sounddevice's names; else portaudio. Why PipeWire's tools by default: the race was ours, but PortAudio's ALSA host API over PipeWire's ALSA plugin is the one place native audio code ran in the daemon, and it's exposed to every graph change (EasyEffects, an add-on's pipe-source loading and unloading). With pw-record/pw-play a driver fault kills a child, which is restarted; PipeWire also relinks the recorder to the new default source by itself. The cost is one pw-play start per sentence (tens of ms). PortAudio's PulseAudio host API wasn't an option: no released PortAudio has it (Arch's 19.7.0 is built with ALSA only), so sounddevice can't pick it.

Command lines: pw-record --raw --format s16 --rate 16000 --channels 1 --latency 32ms [--target <node>] -; parec --raw --format=s16le --rate=16000 --channels=1 --latency-msec=32 [--device=<node>] when pw-record is missing; pw-play --raw --format s16 --rate <sr> --channels 1 --latency 50ms - fed in 4 KB pieces so a stop isn't stuck behind a whole answer in the pipe. A target is passed only with pipewire chosen by name. The Speaker makes a new Player when the setting changes; a new Mic takes it when listening next starts.

Portability

No Linux-only call without a guard: with voice.audio.backend auto (0.8.16) Linux with PipeWire plays through pw-play and records through pw-record; otherwise playback tries sounddevice first everywhere, then pw-play/paplay/aplay only on Linux, afplay on macOS, winsound on Windows; capture is sounddevice (PortAudio is bundled in its Windows and macOS wheels; Linux uses the system's libportaudio) or pw-record/parec on Linux; microphone() asks sounddevice, then pactl on Linux, else "can't tell". Subprocesses it starts are its own children, stopped by their exact pid.
