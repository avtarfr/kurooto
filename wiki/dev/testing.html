Testing

Running the tests

uv sync --locked                    # Python 3.12+, the dev group (pytest, ruff)
uv run pytest -m "not live"         # what CI runs; -q is the default (pyproject.toml addopts)
uv run pytest tests/unit/test_jobs.py -k watchdog
uv run ruff check . && uv run ruff format --check .
  • pyproject.toml [tool.pytest.ini_options]: testpaths = ["tests", "addons"], marker live ("needs real accounts or network; not run in CI"). Never write a test that needs a real account or the internet without that marker.
  • addons/<name>/tests/: each ready-to-publish add-on's own tests. addons/conftest.py imports tests/conftest.py's fixtures (the pretend home, the env fixture) and adds load_addon(name, app) (a git repo made from a copy, fetched and agreed to like a user would, held to its card) and fake_programs({...}) (stand-ins first on PATH that log their arguments). uv run pytest addons/restic-backups runs one.
  • Some tests need Node: tests/unit/test_static_js.py (node --check on every dashboard script), tests/unit/test_livefallback.py (runs tests/js/*.mjs), tests/unit/test_calls.py (the Worker against the crypto vectors). They skip when node isn't on PATH.
  • tests/integration/ runs the real call-line Worker under wrangler dev. It needs Node and the Worker's packages (npm ci --no-audit --no-fund --ignore-scripts in src/kurooto/data/worker, then bundle the call page with npx esbuild web/app.js --bundle --minify --format=esm --target=es2019 --outfile=public/app.js), and skips on Windows or without them (pytestmark in each file).
  • A progress bar for long runs, tqdm-style, with no extra package: start the run with PYTHONPATH=tools uv run pytest -p pytest_progress tests/unit (it writes .pytest-progress.json as tests finish) and watch it from another terminal with python3 tools/pytest_progress.py: tests done of all, rate, time left, and each failure the moment it happens (tools/pytest_progress.py; KUROOTO_TEST_PROGRESS names another file).
  • Android: android/build.sh --test runs the crypto and speech tests on a plain JVM; android/build.sh builds a release-style APK signed with a debug key (needs the Android SDK, a JDK 17 and, the first time, the network for Gradle); --dev a dev build that installs beside the real app (look at its screens with the demo extra, see calls-and-phone.md); --lint the API-level lint.

The real-install guard

tests/isolation.py:start() runs from tests/conftest.py before anything imports kurooto. It makes every test run as if on an empty computer and fails any test that touches the developer's real Kurooto:

  • A pretend home in a temporary folder: HOME, USERPROFILE, XDG_*, APPDATA, LOCALAPPDATA and KUROOTO_HOME (unless set for the run) point into it; Path.home() follows HOME; PYTHON_KEYRING_BACKEND is the null keyring. The autouse fixture nowhere_real gives each test its own fresh pretend home and sets KUROOTO_SECRETS=file.
  • Stand-ins first on PATH (_stand_ins): quiet notify-send / osascript, and loginctl, systemctl, launchctl, kurooto that refuse to do anything.
  • An audit hook (sys.addaudithook(_hook)) refuses and records: opening for write, creating, renaming, deleting or chmod-ing anything under the real install's folders and the places Kurooto changes outside them (protected_paths: the config/data/state/cache folders on every OS, systemd user units, autostart, the app menu, ~/.gemini, ~/.local/bin/kurooto, LaunchAgents, Start-menu shortcuts); opening a SQLite database there (read-only mode=ro URIs excepted); running the real loginctl / systemctl / launchctl / kurooto, or the real programs that change the power mode (POWER: powerprofilesctl, tuned-adm, asusctl, system76-power, powercfg, pmset, sudo, kurooto-legion-night; where they are is noted at start, and a test's own stand-ins elsewhere run as usual: the Night performance add-on's tests); connecting to the running dashboard's port (8770 and whatever the real web.json says); binding that port is refused so test servers move on.
  • pytest_runtest_makereport turns any recorded violation into a failure of that test, whatever it asserted; the terminal summary prints "real-install guard" with violations and reads. Reads of protected folders are only counted.
  • Other autouse fixtures: no_desktop_popups (stand-ins first on PATH), no_path_changes (core/pathfix.allowed returns False), calendar_day_checkins (check-in days start at midnight in tests), no_receipts (jobs.receipt off, so answers end with the AI's words; tests/unit/test_receipt.py turns it on).

If the guard fires, the code under test computed a path without going through core/paths.py:paths() / KUROOTO_HOME, called a real system tool, or reached the real daemon. Fix the code, not the guard.

CLI runs need a scratch KUROOTO_HOME

Outside pytest nothing protects a real install. kurooto <anything> from a source checkout, without KUROOTO_HOME, reads and writes the developer's real settings, secrets, scheduler and notes, can talk to the running daemon through web.json, and some commands change the system (autostart, PATH, agy's settings, the app menu). A development run once changed a live install's settings this way. Always:

export KUROOTO_HOME="$(mktemp -d)"        # or a fixed scratch folder you reuse
uv run kurooto doctor
uv run kurooto run                         # foreground daemon on the next free port, logs in $KUROOTO_HOME/state/logs

With KUROOTO_HOME set, secrets go to a file, the default notes folder is $KUROOTO_HOME/workspace, agy's settings are left alone (providers/agy.py:tools_once unless KUROOTO_AGY_TOOLS=1), and add-on/terminal launchers are redirected (modules/terminal/launchers.py:outside). Still avoid autostart, install-finish, uninstall, export-skills, term --default, rotate and anything that signs in, unless that is what you are testing in a VM. Set KUROOTO_NO_AUTOSTART=1 and KUROOTO_NO_BROWSER=1 for installer experiments (as tools/update_rehearsal.py does).

Buttons

tests/unit/test_buttons.py checks that every button the code sends (("Label", "<prefix>:<ref>:<action>")) has a handler: App.callback's own prefixes or a module's callbacks(). A new button prefix needs its handler in the same change; a string that only looks like one (a scheduler key, log text) goes in NOT_BUTTONS.

Writing a test

def test_something(env):  # a paired app talking to a fake Telegram (tests/conftest.py:Env)
    env.on("reminders")  # App.enable, asserting it worked
    reply = env.say("remind me in 5 min to stretch")
    assert "I'll remind you" in reply
    assert env.app.scheduler.jobs("reminders:")
    text = env.press("rem:abcd:10")  # a button tap; returns the answerCallbackQuery text
  • For code that doesn't need Telegram, build an app directly: monkeypatch.setenv("KUROOTO_HOME", str(tmp_path)); app = App(), and app.close() at the end.
  • Time: core/scheduler.py:Scheduler(..., clock=...) and Quota.clock take fake clocks; run due jobs with await app.scheduler.tick() (or asyncio.run(...)).
  • AI work: set brain.main to a fake (or monkeypatch providers.build), submit, then app.jobs.run_next() runs one job synchronously, including its then-action.
  • Scheduled actions: call them the way the scheduler does, fn(payload), not fn(). Several real bugs (the Space keeper's weekly clean, the concept graph's nightly start) exist because tests called the method directly.
  • Cover each user-visible path: the command, the intent, the button, the tool, and the feature being off (App.handle answers "X is off").
  • Two tests walk everything registered: test_tap.py (a tool or request that sets an alarm, places a call, sends something out... must say so with guarded=, and unattended AI runs must ask first) and test_help.py (every command is in /help, every feature in a group, every request's examples taken by it and shown in /help all, every CORE_SAY example shown and understood by the code that handles it, and the phone app's chat getting the same index). See modules.md.
  • Keep tests hermetic: no network (use a fake on 127.0.0.1), no sleeping on wall-clock time where a fake clock works.

Before you push

uv run ruff check . && uv run ruff format --check .
uv run pytest -m "not live"
python3 tools/privacy_scan.py --staged         # the pre-commit hook does this (git config core.hooksPath tools/hooks)
python3 tools/gen_settings_guide.py --check    # if you touched settings
