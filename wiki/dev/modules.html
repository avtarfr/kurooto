Feature modules

Every feature is a Module subclass (src/kurooto/modules/base.py). All of them are instantiated at startup (App.__init__ loops over modules/catalog.py:CATALOG), whether on or off; a feature is on when its id is in the setting modules.enabled. Nothing is on by default.

What each feature does for the user is described in the user wiki (../user/index.md); this page is about how they are built.

The Module class

Class attributes:

title, descriptionshown on the feature card

heavyTrue: its scheduled work and background task wait for the charger in battery saver mode (core/power.py)

Data classes (modules/base.py):

  • Incoming(text, via="telegram", message_id, files, reply_to, voice, respond); msg.reply(text, buttons=None). via is telegram, terminal (kurooto ask), setup (the try-it box), routine, ...
  • Command(name, help, handler(msg, arg) -> str | None, usage=""). Return the reply text, or None if you replied yourself.
  • Intent(name, description, match(text) -> dict | None, run(msg, slots) -> str, questions=False). questions=True lets it answer questions ("what's due?"); otherwise text that looks like a question goes to the AI.
  • Tool lives in modules/calls/tools.py (see brains.md).

Lifecycle

App.__init__   cls(app) for every class in CATALOG         (no side effects here beyond registering
               overlay.load(app)                            actions/hooks that must exist even when off)
App.start      for each enabled module: m.start(); start_background(m)
App.enable(id) requires on? -> m.ready()? -> modules.enabled += id -> m.start() -> start_background(m)
               -> event module_enabled
App.disable    refuse if an enabled module requires it -> m.stop() -> stop_background(m)
               -> modules.enabled -= id -> event module_disabled
App.close      jobs.halt(); m.shutdown() for enabled modules; scheduler and jobs closed

Rules that follow from it:

  • __init__ runs for every feature, on or off, in tests and in CLI processes. Keep it cheap and free of I/O beyond setting attributes. Register in __init__ only what must work while off: a scheduler action whose one-off jobs may outlive the feature being on (Reminders.__init__ registers reminders.fire), a then-action whose job may finish after a restart (Hints.__init__).
  • start() is called again whenever settings it depends on change in some paths (modules/retro.py:_restart_owner, health's rearm fix), so it must be idempotent: scheduler.every with the same key updates, at(..., replace=False) doesn't duplicate.
  • stop() must call super().stop() (cancels <id>:* jobs), then undo anything else start() set up: hooks in app.availability.blockers, app.ask.hooks, app.updates.holds, notifier channels, event subscriptions. modules/handwritten.py:Handwritten.stop forgets the super() call and its scan keeps running after turn-off.
  • Every scheduled action is called as fn(payload). A method without a parameter fails on every run (modules/space.py:Space.run_clean, modules/integrate.py:Integrate.tick/garden/summary today). Write def x(self, p=None).
  • Long work in a scheduled action blocks the event loop: start a thread.

Settings

Declare at import time, in the module's file, under the module's id:

from kurooto.core.config import register_defaults

register_defaults(
    "pomodoro",
    {
        "minutes": 25,  # how long one session lasts
        "nudge": "daily 09:00",  # when to suggest the first one; "" turns it off
    },
)

This is the only way to declare settings (there's no defaults class attribute). The comment on each line becomes the description in docs/SETTINGS_GUIDE.md; run python tools/gen_settings_guide.py after changing settings (tests/unit/test_settings_guide.py checks it). The dashboard's Settings tab shows every enabled module's section automatically, rendered by value type, and POST /api/settings refuses a value whose type differs from the current one. Read with self.setting("minutes"). Secrets go in app.secrets, never in settings.

Messages, buttons, replies

  • Send with self.app.notify(text, kind=..., buttons=..., map_kind=..., map_ref=..., why="<id>.<reason>", setting=..., about=..., item=...). why="asked" for a direct answer to something the user just did.
  • Every message that comes by itself needs a Calm reason: add an R("<id>.<reason>", "plain words", setting="<id>.<key>", ...) to core/calm.py:REASONS so Why? and Less of this work. See core.md.
  • Buttons: [[("Label", f"{prefix}:{ref}:{action}")]], handled in callbacks()[prefix]; keep the data under 64 bytes.
  • Questions with a hook: self.app.ask.ask(text, choices=[...], hook="<id>.<name>", source=self.id) and self.app.ask.hooks["<id>.<name>"] = fn(q, answer).
  • AI work: self.app.jobs.submit(prompt, ..., then="<id>.<name>") and self.app.jobs.then_actions["<id>.<name>"] = fn(job, result, payload) registered in __init__ or start(). Background work: background=True, a why, and usually quiet=True with the then-action deciding what to say.
  • Events: self.app.events.emit("<id>_<what>", ...), ids and counts only.
  • Notes: always through core/layout.py for paths and core/tools.py:write_note_file for writes; add to the user's notes, never reword or remove their text.

A worked example

A minimal "Pomodoro" feature: a command, an intent, a scheduled nudge, a button, a tool, a Calm reason.

# src/kurooto/modules/pomodoro.py
"""Pomodoro: "start a pomodoro" or /pomodoro starts a timed focus session; a message says when it ends."""

from __future__ import annotations

import datetime as dt
import re

from kurooto.core.clock import now
from kurooto.core.config import register_defaults
from kurooto.modules.base import Command, Incoming, Intent, Module
from kurooto.modules.calls.tools import Tool, arg

register_defaults(
    "pomodoro",
    {
        "minutes": 25,  # how long one session lasts
        "nudge": "",  # e.g. "daily 09:00": suggest one then; "" for never
    },
)

START = re.compile(r"^(start|begin) (a )?pomodoro$", re.I)


class Pomodoro(Module):
    id = "pomodoro"
    title = "Pomodoro"
    description = "Timed focus sessions: /pomodoro, or say start a pomodoro."
    requires = ("telegram",)
    # privacy stays the default: nothing leaves this computer

    def __init__(self, app):
        super().__init__(app)
        # the one-off "session ends" job may fire after a restart, so its action exists from the start
        app.scheduler.action("pomodoro.end", self._end)

    def start(self):
        spec = self.setting("nudge")
        if spec:
            self.every("nudge", spec, self._nudge)  # key pomodoro:nudge, action pomodoro.nudge

    # ---- what it offers
    def commands(self):
        return [Command("pomodoro", "start a focus session", lambda msg, arg: self.begin(arg))]

    def intents(self):
        return [
            Intent(
                "pomodoro",
                "start a focus session",
                match=lambda t: {} if START.match(t) else None,
                run=lambda msg, slots: self.begin(""),
            )
        ]

    def callbacks(self):
        return {"pom": self._button}

    def call_tools(self):
        return [
            Tool(
                "start_pomodoro",
                "Start a focus session for the user.",
                lambda a: self.begin(a.get("minutes", "")),
                {"minutes": arg("length in minutes; empty for the default")},
                offline="queue",
                writes=True,
                hint="When they ask to focus for a while, call start_pomodoro.",
            )
        ]

    # ---- the work
    def begin(self, minutes: str) -> str:
        m = int(minutes) if str(minutes).strip().isdigit() else int(self.setting("minutes") or 25)
        until = now() + dt.timedelta(minutes=m)
        self.app.scheduler.at(until, "pomodoro.end", {"minutes": m}, key="pomodoro:end", module=self.id)
        self.app.events.emit("pomodoro_started", minutes=m)
        return f"Focus until {until:%H:%M}."

    def _end(self, p: dict):  # every action takes the payload
        late = " (late: the computer was asleep)" if p.get("late_s") or p.get("missed") else ""
        self.app.notify(
            f"Pomodoro done{late}.", kind="reminder", why="pomodoro.end", buttons=[[("Another", "pom:x:again")]]
        )

    def _nudge(self, p=None):
        self.app.notify(
            "Start a pomodoro?", why="pomodoro.nudge", setting="pomodoro.nudge", buttons=[[("Start", "pom:x:again")]]
        )

    def _button(self, ref: str, act: str) -> str:
        return self.begin("") if act == "again" else "unknown button"

Then, to make it a real feature:

  1. Add Pomodoro to modules/catalog.py:CATALOG and "pomodoro" to web/api.py:MODULE_ORDER (same position; tests/unit/test_dashboard.py checks the two lists match).
  2. Add the Calm reasons to core/calm.py:REASONS: R("pomodoro.end", "the end of a focus session you started", exempt="own", stop=None) and R("pomodoro.nudge", "a suggestion to start a focus session", setting="pomodoro.nudge", stop=to("", "no nudges")).
  3. If it should be checked daily, add a Check in core/health_checks.py (or return one from health_check()).
  4. Meet the definition of done: a page or section in the user wiki (docs/wiki/user/, and commands.md for the new command), the module reference below, /help (the Command help texts), a CHANGELOG.md line, the site pages; plus docs/MANUAL.md (with its undo), docs/PRIVACY.md if anything leaves the computer, and a regenerated docs/SETTINGS_GUIDE.md.
  5. Tests, with the env fixture from tests/conftest.py:
def test_pomodoro_starts_and_ends(env):
    env.on("pomodoro")
    assert "Focus until" in env.say("start a pomodoro")
    job = env.app.scheduler.get("pomodoro:end")
    env.app.modules["pomodoro"]._end(job.payload)
    assert "Pomodoro done" in env.fake.texts()[-1]

How features are listed and turned on

  • modules/catalog.py:CATALOG is the list of built-in classes (instantiation order; first-wins for duplicate tool names in core/tools.py:agent_tools).
  • web/api.py:MODULE_ORDER is the order the wizard and the Features tab show; add-ons come after (core/overlay.py:status(app)["modules"]).
  • web/api.py:STARTER (telegram, chat, reminders, checkins, deadlines) is the wizard's preset of ticked features. (Not to be confused with providers/openai_compat.py:PRESETS, which are AI services, or core/layout.py:PRESETS, which are notes layouts.)
  • Turning on: App.enable(id) from the wizard (POST /api/modules/enable, or modules/setup which runs setup() and then enables), the dashboard, Google sign-in (which enables the Google parts that became ready), or modules/google.py:GooglePart with_modules.
  • 0.5.8 changes: Attendance is gone. core/upgrade.py:drop_retired (called from App.start) turns a retired feature off on an install that had it, resets its settings and cancels its jobs; class packs keep accepting the old attendance keys and drop them. Exam season is an add-on that ships with Kurooto: Module.extra = True keeps a feature out of every preset (setup.js leaves it out of "Everything") and lists it apart on the Features page (/api/state sends extra).
  • extra versus addon: extra is an optional feature that comes with Kurooto; addon is set by core/overlay.py on features loaded from the user's own add-ons folder.

Add-ons (core/overlay.py)

The "Your add-ons" feature (modules/overlay.py:AddOns, id overlay, settings overlay.path, overlay.code) lays a user's folder over Kurooto:

  • modules/*.py: imported as kurooto_addons.<name> (files starting with _ are helpers, imported by name). Every Module subclass defined in the file is instantiated; its id must match [a-z][a-z0-9_]{1,39} and not collide with an existing feature. Each is off until the user turns it on.
  • skills/<name>/SKILL.md, prompts/*.md, settings.json (defaults between Kurooto's and the user's).
  • guard(app, m) marks m.addon = True and wraps every method in GUARDED (commands, callbacks, replies, intents, help, call_tools, agent_tools, call_brief, classify_intent, status_lines, doctor_checks, health_check) plus ready, health, start, stop, take_files, so an exception is logged (addon_failed, shown by /addons and kurooto doctor) and the call returns a safe default.
  • Extra hooks only add-ons get: classify_intent(text, intents) (runs before the built-in patterns, with classify_timeout seconds, default 2, at most 10; answers under MIN_CONFIDENCE = 0.6 fall through).
  • The folder can't be inside Kurooto's own folders (inside_kurooto), and updates never touch it.
  • Turning add-ons on changes core/places.py:write_roots (their skills/), which makes agy's consent question appear again.

Module reference

One line of purpose and the internals worth knowing. Commands are Telegram commands; "jobs" are scheduler keys (full table in core.md); state is under <state> unless noted.

Channels and conversation

  • telegram (modules/telegram/__init__.py:Telegram, api.py:TelegramAPI): the main channel. background long-polls getUpdates (timeout 50 s, allowed_updates message and callback_query), saving the offset to telegram/offset.json *before* handling each update (at-most-once). Back-off 5-120 s; 409 (another reader or a webhook) waits 30 s; 401 (revoked token) drops the telegram notifier channel until getUpdates works again (a new token), then registers it again. Pairing (pair_start, pair_poll): the token is checked with getMe, a one-hour code in a t.me/<bot>?start=<code> link, accepted only from a private chat; on success telegram.chat_id and telegram.allowed_users = [from.id]. Only allowed_users in a private chat are served; everyone else is ignored. While paused, messages go to telegram/paused.jsonl and are replayed by replay_paused. Files are downloaded into the notes inbox (20 MB Telegram download limit); voice goes to Voice notes. Sending: api.send splits at 3900 chars; past MAX_PARTS (6) it sends the first 5 and a line saying the rest follows, then the whole text as message.txt (with the buttons), so nothing is cut (the job queue sends answers over 7000 chars as a file too); files via sendDocument (captions 1000 chars, no buttons). telegram.focus_end (the end of a /focus) is registered in start(). No 429 handling. telegram/map.json maps sent message ids to {kind, ref} for replies (capped at 3000). The / menu is synced from enabled features (_menu_tick). Commands /pause, /resume, /status, /hold, /calls, /focus; intents hold_calls, calls_ok, focus. Settings telegram.chat_id, allowed_users, silent_kinds, api_base (tests point it at tests/fakes/telegram.py), menu.
  • deadlines call tools (0.5.8): remove_deadline (status "ignored" via _button(id, "drop"), never reopened by _put), unignore_topic; upcoming() leaves out exams already past; full_title() puts the subject's name in front of a bare title; subject_of() checks every folder of a path and the note's own name; _put renames an item when the same source finds it again under a fuller title.
  • chat (modules/chat.py:Chat): free text that isn't a command or intent becomes a job (Chat.ask), and so does a file nothing else took (App.route): its paths are added to the prompt for an agent program to open (no caption: "say what it is"); with Chat off, the reply names what to turn on. Within two hours, the last six turns are prepended. Chat.mine / Chat.owns(jid): only Chat's own jobs are recorded into chat/history.json (see core.md); the set is in memory, so an answer finishing after a restart isn't recorded. Commands /new, /clear, /brain, /usage.
  • cases (modules/cases.py): the Wrong button on answers and a store of requests that fell through; a monthly review can turn one into a test case and teach a phrasing, only if the whole suite still passes. cases/cases.json, never backed up; cases that aren't test cases go after cases.keep_days (0: privacy.keep_days, via core/retention.py:days), and Store.forget(lo, hi) serves /forget. kurooto cases export writes a pytest file. _rephrased(d) runs after the first reply to an understood request: if the draft before it (same channel, REPHRASE_S 180 s earlier) was kept as a fallthrough, the case gets rephrased/rephrased_to; at REPHRASE_TIMES (2) cases with the same norm text and target it calls teach() (the replay gate applies) and notifies with Undo (Calm reason cases.rephrased, event case_rephrased). Setting cases.learn_rephrased.
  • voice_notes (modules/voice_notes.py): transcribe() posts audio to Gemini generateContent; used by Telegram. 18 MB limit.
  • library (modules/library.py): /note into the inbox; /prompts, /prompt (the prompt library in <notes>/prompts).
  • remember (modules/remember.py): "remember that ..." appended to about-me/how-to-help-me.md (health, money and credentials refused by SENSITIVE); help_brief() goes into every AI request's context. keep(app, fact, via, section) is the one path for a fact (Remember's command, intent and call tool, and Learns from its own work's facts); remove_line() takes a line Kurooto added out again, exactly as written (an Undo).

Time and attention

  • reminders (modules/reminders.py): one-off reminders:<id> jobs (reminders.fire, registered in __init__), snooze buttons rem, cancel remx, tool add_reminder. stop() parks the pending jobs in <state>/reminders-parked.json before the base cancel, and start() sets them again (a time that passed while off fires at once with while_off, "late: Reminders was off"). Asks lidsafe whether the phone already said it. The plain-English intent reads the time with modules/text.py:when_from, which takes a weekday only where text.WHEN_DAY says it's the when ("friday at 5pm", "on friday"; "next friday" returns None, to the AI); /remind and /due use core/clock.py:parse_when, where a bare number is minutes.
  • checkins (modules/checkins.py): evening/midday/night prompts by message or call, answers into the daily note; checkins:plan books the day's checkins:<name> jobs; call hooks call_schedule, call_outcome, call_reschedule, call_transcript. A check-in day starts at checkins.day_starts (05:00). learn() (checkins:learn, daily 12:00, checkins.learn_times) reads the last 14 days' plans (<state>/checkins/<day>.json; answered_at is written on a reply and on an answered call; a moved entry counts at its moved time), and with LEARN_MIN_DAYS answered and LEARN_OFF_DAYS 30+ min off on one side sets checkins.times.<name> to the median, rounded to 15 min; <state>/checkins/learned.json keeps from/to/at/undone; button prefix chkl:<name>:undo; events checkin_time_learned/_unlearned; Calm reason checkins.learned.
  • deadlines (modules/deadlines.py): merges deadlines from manual entries, notes tasks, Classroom, the calendar, recurring quizzes and the term note; the hourly deadlines:tick chases them (24 h ping, 6 h call or urgent message, overdue check) and runs exam mode. Ids are hashes of title plus date. deadlines.json under the deadlines lock. The add_deadline tool (and the deadline.add action) takes an optional course (subject, its old name, still works): Subjects.resolve(), else the one subject find_in() names; unknown or naming two, the answer says so and lists the courses, and the item gets no subject from it (subject_of() on the title still applies).
  • deadlines meeting brief: meeting_briefs() (deadlines:meeting_brief, deadlines.meeting_brief daily 20:00) takes open "Meeting: <who>" deadlines due tomorrow whose surname matches a project's With: person (infer.projects_with), builds infer.brief(note, who, due) (Log lines dated on or after Last met, else two weeks; unchecked ## Next steps; the newest ## Meetings line), notifies once (told gets "briefed"; Calm reason deadlines.meeting_brief).
  • deadlines progress: PROGRESS patterns and the deadline_progress intent/tool set parts/parts_done on an open deadline found by find_open() (similar() on the title or the full title, the soonest due); parts_text() adds "(4/7)" to lists and the call brief; Start-by's size_of() scales _whole_size() by what's left.
  • startby (modules/startby.py): start-by dates from size estimates and free time; local arithmetic only. learn_window() (startby:learn_window, weekly sun 12:00, startby.learn_window) reads message_in events of the last 21 days (a day turns at 04:00), and with 7+ days of 3+ messages sets startby.window from the medians of the first and last, clamped and rounded to 30 min, when either end is 60+ min off; skipped when the user's own value isn't the last learned one. State window_learned in startby.json; Undo is sby:window:undo; Calm reason startby.window.
  • exam_season (modules/exam_season.py): one card for an exam period (update hold, alarm check, the eve question, leave-by alarm, debrief, no calls in exams, the Calm budget). Registers app.updates.holds["exam_season"] and an availability blocker; budget_during_exams() is read by Calm. An add-on since 0.5.8 (extra = True). Its revision part is modules/revision.py (not a module: ExamSeason.revision, a Revision, settings in exam_season.*): topics() reads the exam prep note's "Covered so far"/"Gaps" lines, else dated lecture notes, else concept notes (integrate's chapters.json, the subject folder); ranked() sorts by rank_key (tier: no note, stub by body_words() < STUB_WORDS, weak recall < WEAK; then recall, course order), recall being the last grades of the topic's quiz items (_items: they name it or link its note) and its own last answer; plan() lays them with the pure lay() into startby.slots() less commitments and the exams (minus()), soonest exam first, at most Start-by's size_of() hours per exam; reading() lists the note, then core/studypack.sources() pages (class material first) and the concept graph's seen.json pages. The day's blocks are fixed in revision.json the first time (today(), also from the tick, the card and StartBy.morning_rows/morning_lines, which append them). The tick sends ask() once a day (Calm reason exam_season.revise); buttons rv:<yyyymmdd>-<n>:y|p|n go to answer(), which grades the quiz items through Quiz.grade and keeps their previous state for undo() (Quiz.restore). Commands /revise, intent "what should I revise today". Tests: tests/unit/test_revision.py.
  • alarm (modules/alarm.py, requires calls): the wake-up call is booked on the call line so it rings with the computer asleep; alarm:plan every 30 min; the morning plan drafted prep_min before; sets app.availability.sleep; mirrors to reserve/alarm.md. Alarms you set are a list (alarm-set.json, mine(), at most MAX_SET); the scheduler holds one ring (alarm:ring), the soonest of that list and the daily alarm (_plan); _ring drops the one ringing, call_schedule() sends every one still to come (upcoming()) to the line, and next_daily() treats a morning with one of yours as had. clear() the next, clear_at("HH:MM"), clear_all() (the daily alarm stays). script() opens with the current local time and only asks about classes still to come.
  • lidsafe (modules/lidsafe.py, requires calls): seals the next day's reminders for paired Android phones (s1) and hands them to the call line, so they arrive with the lid shut; whichever side is awake says each once.
  • awake (modules/awake.py): holds a sleep inhibitor on mains power (core/inhibit.py).
  • calendar (modules/calendar.py): iCal links (secret calendar.ics) and Google Calendar, recurrences expanded, private events masked; blocks calls during events, #focus and #nocall; calendar:refresh every 15 min. Each stored event has a src (ics:<hash of the link>, google:<account>); a source that fails keeps its rows from the last copy (google_calendar.fetch returns the failed accounts by name).
  • weekly (modules/weekly.py): Sunday summary from events.jsonl and modules' weekly_lines; optional review call.
  • quests (modules/quests.py): one onboarding quest a day for a week, judged from the event log.

Study

  • subjects (modules/subjects.py): subjects, timetable, holidays, exam periods, the term note (modules/termnote.py parser); a call blocker during classes; class packs layered under. Missed-class catch-up: catch_up(), job subjects:catch_up every 30 min; classes over today that were skipped or ended before woke_at(day) (the first message_in, alarm_up_now or call_answered after checkins.day_starts) get a deadlines.add(..., source="catch_up", kind="task") due at the course's next class and a lecture stub; state subjects/catchup-<date>.json; button cup:<date>|<slug>:went; Calm reason subjects.catch_up. With Classroom on (google with google.classroom, or classroom_notes), google_classroom.posts_on(app, slug, day) gives that day's posts of the courses filed under the subject (classroom_notes.folders, classroom-notes/folders.json, else course_subject(), the longest subject name in the course's name) from classroom-posts.json (remember_posts, called by Google.classroom_sync and ClassroomNotes.fetch); they end the message line and go under ## Classroom posts that day in the stub. Each run, _more_posts rewrites that list in a stub still the size it was made (size and posts in the catch-up file), so posts that come later that day join it.
  • commitments (modules/commitments.py:Commitments): commitments.items rows {name, days, start, end, calls}; on(day) gives a day's with start_dt/end_dt (an end before the start runs into the next day); the call blocker commitments checks yesterday's and today's (night shifts); skips per day in <state>/commitments/skip-<date>.json; /busy (add splits the words as the first split whose rest parse_days reads), intent skip_commitment, call tool skip_commitment, brief commitments_today. Distinct from Skills' /every routines.
  • classpacks (modules/classpacks.py, format in modules/coursepack.py): import/export a section's setup as a .kurooto-course file with a strict schema that refuses personal data.
  • capture (modules/capture.py): after each class, a question about what was worth keeping; answers to the class log, a study-log skill job with Chat on.
  • doubts (modules/doubts.py): a per-subject doubts list, sent before the next class.
  • quiz (modules/quiz.py): spaced repetition over "must know" bullets in exam-prep notes; graded by the AI with Chat on; calls with Phone calls on. Tools quiz_next, quiz_grade, schedule_quiz. Link recall cards (modules/quiz_links.py:LinkCards, Quiz.links): every - relation:: [[target]] — reason line between two concept notes (conceptgraph.scan) is a card in the quiz's own storage (quiz/_links.json, Quiz.load / Quiz.grade, so the same SM-2-lite spacing and history), with a, b, relation, reason, names, subject (from integrate/seen.json's book key, else the note's folder) and gone for a link that's no longer there. Reply kind qlink, buttons ql:<id>:<0|3|4|5>; the reveal's "Where to read" is the seen.json pages of both concepts plus sources.pick over sources.notes_material (own notes, Classroom files). A reply from the phone app gets the grade buttons as a new message (why="asked"): the app's reply note can't carry buttons. LinkCards.tick (quiz:links at quiz.links_at, and quiz:links:later after a block) sends one with Calm reason quiz.links when quiz.links is on, fewer than links_per_day (capped at MOST = 5) came today, the last one was answered, and busy() (focus, a call, the night, any non-focus availability blocker such as a class) is clear. quiz.links_check: one sentence from the profile's helper model through LocalModels.api("/api/generate"), only with Local AI models on. /card (doesn't count toward the day), /cards [on|off]. Tests: tests/unit/test_link_cards.py.
  • hints (modules/hints.py): a hint ladder for a problem, respecting a course's AI policy line.
  • study (modules/study.py): minutes per subject from the focused window title (read and discarded), idle and lock aware (core/idle.py); Windows GetForegroundWindow, macOS System Events, Linux hyprctl / swaymsg / xdotool.
  • skills (modules/skills.py): runs SKILL.md files (shipped data/skills, add-ons, prompts with skill: true, the user's own) as AI jobs; routines (/every), drafts (/newskill), LaTeX revision packs (Tectonic --untrusted, else latexmk or pdflatex with -no-shell-escape: the AI wrote the LaTeX), study packs, send_file(s) (over 50 MB goes to Drive upload).
  • books and integrate: see concept-graph.md.
  • handwritten (modules/handwritten.py): transcribes PDFs and photos from an inbox folder (local vision model or Gemini) into Markdown; stop() cancels its handwritten:scan job and halts a scan in progress. Then modules/handwritten_links.py (Linker, hw.linker) links the note like any other: _file calls linker.submit(note, src), which works out when the pages were written (written_times: the PDF's CreationDate/ModDate, a stamp in the scan's name, the file's mtime) and the class by time (class_for: during a class ±10 min, else the last class that ended earlier that day, via subjects.classes_on), gets candidates from conceptgraph.Index.candidates (integrate.index() when the concept graph is on, else a keyword-only index), and queues one job (lane="chk", brain = integrate.roles()[1] or brain.main, then="handwritten.linked", registered in __init__). Linker.done/apply then: title (only when the heading still looks like the file name and nothing of the user's is above the marker), subject (a "during" class wins, else the AI's slug, else the class before), header (aliases, tags, course:), a ` block right after the closing marker with ## Links (lecture, course page, AI-picked concepts: must exist, graphwrite.lint_reason`, confidence ≥ 0.5, at most
  • and ## Doubts, the course page's ` block (graphwrite.put_block, checked by guarded). yours() must be unchanged or nothing is written. Before-copies per run in <state>/handwritten-undo/ (last 60; /handwritten undo restores only files still as written); /handwritten link (link_all) queues every transcription without a Links section as one batch (one message at the end), skipping ones already queued. State: <state>/handwritten-links.json. Tests: tests/unit/test_handwritten_links.py`.

Notes, sync and safety

  • notes_sync (modules/notes_sync.py): git add/commit/fetch/rebase (or merge keeping both)/push to a private GitHub repository; refuses public repos; the token is passed through GIT_CONFIG_* environment variables, never argv; never force-pushes; pushes a couple of minutes after AI jobs (notes_sync:soon). Shares the repo with the call line.
  • gbrain (modules/gbrain.py): the GBrain notes index (Bun + PGlite) in <data>/gbrain, synced every 15 min; "external" mode for the user's own GBrain; shares the gbrain lock with backups.
  • local_models (modules/local_models.py): installs Ollama and the models the hardware profile suggests; wires the helper model into brain.models.ollama and brain.classify; rest() unloads models on battery.
  • backups (modules/backups.py): a daily zip of config, data and state (notes, secrets, the GBrain index optional) to a folder the user picks; SQLite copied with the backup API; kurooto restore.
  • profile (modules/profile.py, crypto in core/profile.py): the setup, encrypted with the user's passphrase, on a branch of a private repository; restore on a new computer.
  • space (modules/space.py): the Space keeper (see core.md).
  • overlay: add-ons (above).

Google

modules/google.py:Google is the sign-in hub (OAuth with PKCE through the user's own Desktop client; tokens in secret google.tokens[.<account>]; redirect to http://127.0.0.1:<port>/oauth/google) and Classroom/Gmail drafts. GooglePart subclasses each need their own scopes: classroom_notes (google_classroom.py, Classroom posts and Drive files filed into notes by an AI job), mail_digest / reply_drafts / digest_email (google_mail.py), agent_plan (google_plan.py, its own calendar of time blocks; reschedule(start, by) deletes today's blocks not done and plans them again from start (or each by later), keeping order, lengths and gaps up to GAP_MAX, dropping a repeated title, stopping at LATEST_H; undo in agent-plan.json; intent reschedule_day, call tool reschedule_day), google_calendar (google_calendar.py, read-only), drive_upload (google_drive.py, resumable uploads; temporary uploads expire after drive_upload.temp_days: expire deletes each as the account recorded with it, and only while the file's parents still hold the Kurooto folder it went into; a moved, trashed or unknown-folder one is forgotten, not deleted). google_confidential.py is a helper for summarising confidential mail with a local model. An HTTP 401 from an API drops the access token and tries once more with a new one (Google.api, DriveUpload._call); only invalid_grant when renewing it is a lost sign-in (_lost_signin drops the refresh token). Then-action google.draft (an AI-written /draft) is registered in start(), so one finishing after a restart arrives.

Computer

  • calls: see calls-and-phone.md.
  • terminals (modules/terminals.py): live PTYs behind the dashboard's Terminals tab (UnixPty via os.openpty, WinPty via pywinpty/ConPTY), 400 KB replay buffer, input 100 KB per request.
  • terminal (modules/terminal/): Kurooto Terminal, a real terminal window (kurooto term): plan.py decides tabs, shell and terminal program; kitty.py (Linux, macOS) and wt.py (Windows Terminal fragment) draw it; look.py turns the palette into a terminal scheme; launchers.py adds app-menu entries; defaults.py (opt-in) makes it the default terminal and can undo exactly what it changed; run.py is the CLI.
  • research (modules/research.py): a weekly papers digest (arXiv, bioRxiv, medRxiv, PubMed, feeds), daily project logs from git and runs/, and questions about idle projects. papers() collects with mark_seen=False and marks them in research-papers.json once delivered: right after the plain digest, or in the research.digest then-action when the AI-picked one succeeded.
  • retro (modules/retro.py, requires chat): the nightly look back proposes setting, profile, skill and idea changes, each confirmed through app.ask; only settings in TUNABLE (and modules' tunable) may be proposed. With Learns from its own work's remember part on (Learning.picks_facts()), _run appends learning.REMEMBER_ASK to the instructions, adds chats (the day's own requests, Learning.chats) to the input, and hands the answer's remember list to Learning.keep_facts, which keeps them without a tap.
  • dreaming (modules/dreaming.py:Dreaming): morning (dreaming:morning, dreaming.when) builds one message from the event log since the last one (since(): <state>/dreaming.json, at most 30 h back): night() counts integrate_batch, book_read, integrate_pruned, handwritten_linked, gbrain_upkeep, call_reviewed, learning_skill_learned/_improved, learning_remembered, inferred; loose_ends() reads open doubts (## Doubts bullets in notes changed in 14 days), Integrate.metrics() (broken, no links in), past-due tasks (Deadlines.upcoming), job_failed events. No AI. Integrate.summary doesn't send its own line while it's on. /dream shows it without marking it sent. Calm reason dreaming.morning. self_check(ev) (dreaming.self_check): counts case_kept events (missed vs wrong), then with Cases on runs cases.suite() and reports test cases in fail whose id was in the stored passing list (<state>/dreaming.json), emitting dreaming_regressed; only the sent morning message replaces passing. A suite error emits dreaming_check_failed and skips the check.
  • learning (modules/learning.py:Learning, requires chat, extra = True): "Learns from its own work", four parts each behind a setting (learning.search, skills, corrections, remember; part(name) is the feature and the part both on) and a card toggle (card, card_action, PARTS).
  • Search: History keeps an SQLite FTS5 table docs(title, body, key, kind, at) in <state>/learning/history.db (a plain table matched with LIKE when this Python's SQLite lacks FTS5). update() adds only what's new: jobs from Jobs.finished_since(mark) (lane you, not learning.* then-actions; the request text through asked(), which drops Chat's earlier turns and a skill's RULES), transcripts by file mtime (marks table), chat turns newer than the last one, skipping a turn whose answer hash is already indexed (answers table). It runs every 15 minutes (learning:index, in a thread) and before each search() (all words with prefix match, then any word; bm25 with the title weighted 4x). /history [Nd] <words>; tool search_history (agent_tools(), so unattended runs of every brain get it, not calls). core/space.py:history_items prunes items older than space.jobs_days; footprint shows the index on its own; Backups skip it (SKIP_STATE_FILES).
  • Skills from experience: _finished is a Jobs.watchers entry (registered in __init__, gated on the feature). For an ok job in lane you with no then-action and at least skill_min_steps steps (the tool log, or usage["tool_calls"]), at most CHECKS_A_DAY a day, judge_skill submits LEARN_SKILL text-only, low effort, background, lane chk, on check_brain() (learning.brain, else modules/integrate.py:Integrate.roles()[1]), then-action learning.skill. _skill_judged reads NONE / IMPROVE <name> + bullets / NEW + a fenced SKILL.md. New: make() must accept it, no existing skill may share its name or mostly its words (similar, a Jaccard of 0.5 over name and description), not a command name; written with stamp() (learned: true, learned_from, learned_on; internal: dropped) via write_note_file(create=True) into skills.user_dir. Improve: tips under "## Learned from experience" through _change.
  • Corrections: _finished also remembers the last skill answer (then skills.done/skills.latex) in state.json. heard(msg, text) is called from App.handle for every non-reply message that isn't a command (it never consumes it): CORRECTION within CORRECTION_WINDOW_S of that answer. Skills._again (a reply to a skill's answer) calls corrected(..., replied=True), which needs CORRECTING words. LESSON goes to the same lane and brain (then-action learning.lesson): LESSON: ... adds a line under "## Lessons"; REWRITE + a fenced file replaces it only if the file is unchanged since (base hash), still a skill with its header, and 0.5 to 2x the old length.

Known problems (as of this writing)

  • modules/telegram/api.py: there is no 429 (flood limit) handling.
  • modules/chat.py:Chat.mine lives in memory: an answer that finishes after a restart isn't recorded into the history, and list(self.mine)[-50:] keeps an arbitrary 50 ids rather than the newest.
  • modules/hints.py:policy_kind tests "no solutions" before "no AI", so a policy line saying both is read as hints allowed.
  • modules/research.py: papers are marked seen before the AI-ranked digest is delivered; a failed digest loses them.
  • modules/capture.py and modules/checkins.py declare no privacy and inherit "Stays on this computer.", though with Chat on their content goes to the AI. modules/google_mail.py:MailDigest.privacy says confidential mail is never read, but mail_digest.confidential = "local" has a local model read it.
  • modules/skills.py:compile_tex passes -no-shell-escape to pdflatex but not to latexmk.
  • modules/calendar.py:Calendar.refresh keeps the old copy only when every link failed; one failing link among several silently drops that link's events.
  • modules/classpacks.py: attendance_rules, attendance_rule and class_kind have no callers once Attendance is removed.
  • modules/learning.py: only the last skill answer is remembered for a "no, ..." correction (state.json last_skill), so a correction meant for an earlier skill answer goes to the latest one. The duplicate check for a learned skill compares words of names and descriptions only, so a reworded duplicate can slip through. The tool log is in memory: a request that finishes after a restart counts only the steps since.
