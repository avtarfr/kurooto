The notes sorter (developers)

User-facing: ../user/notes-and-concept-graph.md. Added in 0.7.4. Code: core/sorting.py (logic, no AI), modules/sorter.py (the feature), core/notesfit.py (the move machinery it reuses). Tests: tests/unit/test_sorter.py.

The rules it keeps (each has a test)

  • Never deletes, merges or overwrites (sorting.free_name numbers a taken name; notesfit.apply_plan(keep=...) keeps the scratch folder even when it's emptied; test_a_note_with_a_subject... compares every file's content hash before and after).
  • Only the scratch folder moves (sorting.ready); a place is only a folder that exists, two levels down at most, never Kurooto's own (sorting.folders, SKIP_DIRS, private_dirs); the scratch folder can't point outside the notes (scratch_rel: no .., no absolute path, nothing hidden).
  • Your text is never rewritten. sorting.plan uses notesfit.plan_moves, which fixes links in Kurooto's own text only and counts those in yours (Plan.theirs); a note with any inbound link of yours waits (plan checks each move alone when theirs is non-empty).
  • Undo is notesfit.undo on the pass's move log (<state>/notes-moves/), so /sort undo restores notes and fixed links exactly; sorting.undo also forgets the moved entries so they aren't learned from.

Flow of a pass (Sorter.run)

  1. sorting.learn (a note it moved that's gone from its place: found by name and content hash elsewhere = your correction: a rule {keys, folder} and a pin by hash).
  2. For each ready note: sorting.decide (learned rules, subject:/course:/class:, a tag, one subject named in the title; two subjects named is ambiguous: it waits with both as guesses). Sure enough (min_conf) and under the nightly limit: a move. Otherwise, with sorter.ai on and not asked in the last day: one job (sorting.prompt, lane "bg", text only, quiet) whose result comes to Sorter._decided; else it waits.
  3. Sundays and /sort now: sorting.recheck (a first look a week after the move, then monthly; only rule or learned matches at 0.85 or more; pinned and corrected notes skipped).
  4. Sorter._move: sorting.plan then sorting.apply (one log); one Calm message sorter.summary with Undo (srt:<log>:undo).

sorting.answer trusts nothing from the AI but an existing folder and a confidence in 0 to 1 (a bad folder, ../.. or a low confidence leaves the note waiting: test_a_bad_or_unsure_ai_answer_leaves_the_note_alone).

State and settings

<state>/sorter/state.json: moved (by current path: from, content hash, time, count, keys), rules, pinned, waiting (with the best guesses and a button id), passes, day (today's count). moved entries expire after 60 days. Settings sorter.* (SETTINGS_GUIDE.md); the module's switch is Features. Tap table: tap.BY_ITSELF["notes.sort"] (a change it makes by itself, with Undo).
