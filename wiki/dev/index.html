Kurooto developer wiki

Kurooto is a personal assistant that runs on its owner's computer: one Python daemon with an in-process scheduler, a queue of AI requests run by "brains" (agy, Claude Code, a Gemini key, Ollama, any OpenAI-compatible service), a Telegram channel, a local web dashboard and setup wizard, opt-in feature modules, phone calls through a per-user Cloudflare Worker and an Android app, a concept graph that weaves books into a Markdown notes folder, and signed self-updates.

This wiki is for people and AI agents who change Kurooto's code. A full read should be enough to find your way, fix a bug or add a feature without help. For using Kurooto, see the user wiki (../user/index.md) and docs/MANUAL.md; for helping a user set it up, the repository's AGENTS.md.

Definition of done (the owner's standing rule): every change updates, in the same commit, the user wiki (docs/wiki/user/), this developer wiki, /help, CHANGELOG.md and the site pages tools/release.py publishes. No change is done until those match the code. Details in agents.md and conventions.md.

Every claim points at code as path:symbol (paths under src/kurooto/ unless they start with tests/, tools/, docs/, android/ or installer/). When the code and this wiki disagree, the code wins: fix the wiki.

Reading order

  1. architecture.md: the daemon's pieces, startup and shutdown, and a message end to end.
  2. repo-layout.md: every folder and important file.
  3. core.md: settings, secrets, paths, every file Kurooto writes, the scheduler and every scheduled job, AI jobs, events, notify and Calm, questions and approvals, availability, power, presence, free limits, the reserve, the space keeper, hardware profiles, locks, Windows notes.
  4. brains.md: the brain interface, each provider, effort, fallback, the tools AI gets, MCP, allow-lists, adding a brain.
  5. modules.md: writing a feature (with a worked example), lifecycle, listing and enabling, add-ons, and a reference of every module.
  6. web.md: the HTTP server, auth, every API route, live events, the front end, the Today page actions.
  7. calls-and-phone.md: the call line, connector, ringing, fallbacks, transcripts and the post-call look back, pairing, crypto, the Android app.
  8. concept-graph.md: books → segments → candidates → AI batch → checks → safe writes → ledger → garden.
  9. testing.md: running tests, the real-install guard, scratch KUROOTO_HOME, fakes, CI.
  10. release-and-updates.md: versions, the changelog, building, signing, channels, the updater, rollback.
  11. conventions.md: house style, privacy rules, the privacy scanner, what never to commit.
  12. debugging.md: doctor, logs, events, the diagnostics bundle, common failures.
  13. agents.md: for AI coding agents: what to read, invariants, checks, what never to do, how to report.

Short on time: architecture, then the page for your area, then testing and conventions. AI agents: start with agents.md.

Quick start for a developer

git clone <the repository> && cd kurooto
uv sync --locked
git config core.hooksPath tools/hooks          # privacy scan and identity checks on commit and push
uv run pytest -m "not live"
export KUROOTO_HOME="$(mktemp -d)"             # never run the CLI against a real install
uv run kurooto run                             # the daemon in the foreground; open the URL it logs
